# Установка демостенда

## 1. Подготовить компьютер

Нужен Docker с Compose v2. На Mac установите и запустите Docker Desktop; на Linux — Docker Engine и Compose plugin. На Windows используйте Docker Desktop с интеграцией WSL 2 и выполняйте команды в терминале Linux внутри WSL. Скрипты проекта рассчитаны на shell, а не PowerShell.

Проверьте в терминале:

```sh
docker version
docker compose version
```

Если первая команда сообщает, что сервер Docker недоступен, сначала запустите Docker. На Apple Silicon ONLYOFFICE работает через эмуляцию amd64; первый запуск может занять несколько минут.

## 2. Скачать проект

С Git:

```sh
git clone https://github.com/gdmnmad/suitecrm-onlyoffice-hr.git
cd suitecrm-onlyoffice-hr
```

Без Git: на странице репозитория нажмите **Code → Download ZIP**, распакуйте архив. Откройте терминал в распакованной папке `suitecrm-onlyoffice-hr-main`, где лежит `compose.yaml`. Все следующие команды выполняются из этой папки.

## 3. Запустить локально

```sh
sh scripts/start.sh
```

Скрипт сам создаст `.env` из `.env.example`, соберёт CRM и запустит базу, ONLYOFFICE и очередь. Не закрывайте Docker Desktop во время работы. При первом запуске дождитесь установки CRM и готовности контейнеров.

Откройте [http://localhost:8080](http://localhost:8080).

| Пользователь | Пароль нового локального демо | Доступ |
|---|---|---|
| admin | demo-admin-change-me | Администрирование и шаблоны |
| hr_editor | demo-hr-change-me | Кадровые данные и генерация |
| hr_viewer | demo-hr-change-me | Просмотр |

Если `.env` уже изменён, используйте заданные в нём пароли. Изменение `.env` само по себе не гарантирует смену пароля существующей учётной записи в базе: меняйте его через администратора CRM. Не используйте локальные демопароли для открытого сервера.

На главной странице выберите «Сотрудники». Уже созданы три вымышленные карточки и три шаблона. Дальше следуйте [руководству кадровика](USER_GUIDE.md). Кадровая карточка и учётная запись для входа — разные сущности.

## 4. Остановить и снова запустить

Посмотреть состояние:

```sh
docker compose -f compose.yaml -f compose.cmwedding.yaml --profile office ps
```

Остановить с сохранением данных:

```sh
docker compose -f compose.yaml -f compose.cmwedding.yaml --profile office down
```

Снова запустить:

```sh
sh scripts/start.sh
```

Данные находятся в Docker volumes. Команда `down -v` удаляет эти данные. Копия репозитория не содержит вашу рабочую базу и созданные документы.

## 5. Если не запускается

- **Permission denied при запуске скрипта:** используйте `sh scripts/start.sh`.
- **Порт уже занят:** освободите 8080 и 8082 либо настройте порты Compose и соответствующие адреса в `.env` согласованно.
- **Истекло ожидание запуска:** контейнеры могли продолжить установку. Посмотрите состояние и логи, дождитесь завершения; затем повторите запуск. Не удаляйте volumes для исправления ожидания.
- **Нет кадровых пунктов меню:** обновите страницу после готовности установки. Список сотрудников доступен по `http://localhost:8080/#/HR_People/index`.
- **Редактор или генерация недоступны:** проверьте готовность ONLYOFFICE и очередь в списке контейнеров. Адрес `ONLYOFFICE_PUBLIC_URL` должен открываться в браузере пользователя.
- **Форма сообщает ошибку:** исправьте перечисленные поля. Параметры документов сохраняются в текущей сессии; после выхода или истечения сессии они могут быть недоступны.

Логи:

```sh
docker compose -f compose.yaml -f compose.cmwedding.yaml --profile office logs --tail=100 crm onlyoffice office-mq
```

Для сообщения о проблеме приложите текст ошибки и логи, предварительно убрав пароли, токены и персональные данные.

## 6. Установить на отдельный сервер

Скачайте проект на сервер с Docker и актуальным Compose v2. Серверный override использует `!override`; если Compose не понимает этот тег, обновите Compose.

```sh
cp .env.server.example .env
```

Отредактируйте `.env`: замените `YOUR_SERVER_IP` реальным IP или доменом в обоих URL, задайте уникальные пароли во всех переменных и длинный случайный `ONLYOFFICE_JWT_SECRET`. Затем:

```sh
docker compose -f compose.yaml -f compose.cmwedding.yaml -f compose.server.yaml --profile office up -d --build --wait --wait-timeout 360
docker compose -f compose.yaml -f compose.cmwedding.yaml -f compose.server.yaml exec -T crm php /opt/checks/server-post-migration.php
```

Вторая команда применяет серверные пароли трём учётным записям из `.env`. Выполняйте её после готовности CRM. Откройте `http://ВАШ_IP:8080`; редактор использует `http://ВАШ_IP:8082`. Разрешите доступ к этим портам в настройках сервера. `localhost` в публичных URL указывать нельзя: у посетителя он означает его собственный компьютер.

Серверная конфигурация публикует порты наружу. Для размещения реальных кадровых данных настройте HTTPS и актуальную поставку ONLYOFFICE: текущая сборка — старый демонстрационный выпуск. Не публикуйте `.env`, резервные копии базы и ключи в Git.

При дальнейших командах управления сервером всегда указывайте все три Compose-файла, как в примере выше. Перенос существующих данных требует отдельной резервной копии volumes/базы; обычный `git clone` создаёт новый стенд с демоданными.
