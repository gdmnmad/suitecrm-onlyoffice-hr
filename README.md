# Кадровый демостенд SuiteCRM и ONLYOFFICE

Основа демо — проверенный патченный образ `cmwedding/onlyoffice-licensed` версии 7.2.2.56. Дальнейшие изменения интеграции проверяются на этой конфигурации; она запускается по умолчанию через `scripts/start.sh`.

Три вымышленных сотрудника, руководитель и подчинённые, награды, периоды службы, образование и родственники. Три заранее созданных DOCX-шаблона: рапорт на отпуск, список наград, послужной список. Генерация выполняется ONLYOFFICE через `/docbuilder`, редактирование — в его браузерном редакторе.

## Запуск

Нужен запущенный Docker Desktop / Docker Engine с Compose. Для экспериментального ONLYOFFICE используется amd64; на Apple Silicon — эмуляция.

```sh
./scripts/start.sh
```

Скрипт создаёт `.env` из примера, если его ещё нет, и запускает Compose с проверенным образом cmwedding ONLYOFFICE 7.2.2.56 и отдельным RabbitMQ. Возврат к исходному Community 6.3.1.32: `./scripts/start.sh legacy`. Первый запуск собирает зависимости и устанавливает CRM; ONLYOFFICE может запускаться несколько минут.

CRM: http://localhost:8080

| Логин | Назначение | Пароль в `.env` |
|---|---|---|
| admin | Администратор, настройка и шаблоны | CRM_ADMIN_PASSWORD |
| hr_editor | Кадровик, изменение и генерация | HR_DEMO_PASSWORD |
| hr_viewer | Просмотр карточек и документов | HR_DEMO_PASSWORD |

По умолчанию демопароли: `demo-admin-change-me` и `demo-hr-change-me`. Порты привязаны к localhost. Для использования вне локального демонстрационного стенда настройте пароли, HTTPS и актуальную поставку ONLYOFFICE.

## Главная страница

`/#/home` открывает рабочее место кадровика. Карточки CRM сгруппированы, списки показывают полезные поля, верхнее меню CRM содержит кадровые разделы, включая документы, шаблоны и инструкции. Над списком сотрудников есть явная кнопка создания. При обновлении конфигурации перезагрузите страницу, чтобы CRM получила новый набор маршрутов. Общие страницы: [документы](http://localhost:8080/legacy/index.php?entryPoint=HrLibrary), [шаблоны](http://localhost:8080/legacy/index.php?entryPoint=HrTemplates), [аудит](http://localhost:8080/legacy/index.php?entryPoint=HrAudit), [инструкции и образцы](http://localhost:8080/legacy/index.php?entryPoint=HrGuide). Панель учитывает доступ пользователя.

## Что показать

1. Открыть «Сотрудники»: руководитель Соколов и подчинённые Орлов и Лебедева. Кадровая карточка отделена от логина CRM.
2. В карточке раскрыть Relationships: награды, служба, образование, родственники. Награды и периоды — отдельные записи.
3. Изменить приказ у награды или добавить период службы. Открыть «Аудит кадровых данных»: там автор, операция, время, старые и новые значения. Мягкое удаление сотрудника удаляет его дочерние записи с аудитом.
4. Нажать ссылку «Сформировать документ» в карточке. Выбрать шаблон; для отпуска указать даты и раскрыть «Дополнительные поля рапорта по образцу»: адресат, ФИО в дательном падеже, причина, место, транспорт, следующий отпуск, возвращение и согласующие. Продолжительность считается включительно. Получить DOCX/PDF, открыть результат в ONLYOFFICE.
5. Показать Лебедеву: в списке наград написано «Наград нет». В послужном списке пустая дата окончания означает «по настоящее время».
6. Администратор в разделе «Шаблоны» может создать копию поддерживаемого шаблона и открыть её в ONLYOFFICE для изменения. Копия становится доступной в форме генерации. Сохраняйте теги content controls: `person`, `manager`, `leave`, `signature`, `awards`, `service`; в рапорте — блоки `leave.*`. Для скалярного поля можно использовать `person.<имя поля>`.

После первой авторизации SuiteCRM может показать мастер профиля. Доступ к кадровым модулям — через меню или адрес `/#/HR_People/index`. К карточке также можно перейти по ссылке в списке.

## Сохранение документов

Форма сохраняет введённые параметры в текущей сессии отдельно для пользователя и сотрудника. Ошибки перечисляются и показываются возле полей. Успешная генерация перенаправляет на GET, поэтому обновление страницы не повторяет отправку. У результата сохраняются снимок данных, автор, время создания, версия и хеш шаблона. Изменение CRM не меняет уже сформированный документ. Результаты доступны в истории на странице документов сотрудника. Изменения в редакторе сохраняются в DOCX через callback; исходный PDF остаётся результатом первоначальной генерации. Аудит приложения не защищён от администратора базы.

## ONLYOFFICE и патчи

В основном `compose.yaml` оставлен официальный Docs 9.4.0. Рабочее демо использует `compose.cmwedding.yaml` с образом cmwedding ONLYOFFICE 7.2.2.56, закреплённым по digest. API подтвердил действие патча: 9999 соединений и advanced_api=true; все 9 генераций и callback прошли. Встроенный RabbitMQ падает под amd64-эмуляцией на Mac, поэтому добавлен отдельный официальный RabbitMQ. Подробности: [протокол проверки](docs/cmwedding-test.md). Это старый архивный выпуск для локального демо; переход на актуальную поставку остаётся отдельным этапом. Резервный `compose.legacy.yaml` использует исходный Community 6.3.1.32 с лимитом 20 соединений.

`aleho/onlyoffice-ce-docker-license` проверен в `compose.patched.yaml`: серверные бинарники удалось собрать, но публичный тег не содержит требуемого PostgreSQL-коннектора, и DocService не запускается. Патч не используется в рабочем стенде. Исходники и изменения сборки описаны в `docker/onlyoffice-patched/PROVENANCE.md`.

Резервный Zegorax проверен отдельно: ожидаемый PEM-ключ не найден в выбранных Developer-бинарниках, сборка намеренно останавливается. Этот override не используется в скрипте запуска. `compose.baseline.yaml` — диагностический исходный Developer-сервер, применявшийся для проверки интеграции, не основной запуск.

## Проверки и управление

```sh
docker compose exec -T crm php /opt/checks/check-crm.php
docker compose exec -T crm php /opt/checks/check-permissions.php
docker compose exec -T crm php /opt/checks/check-delete.php
docker compose exec -T crm php /opt/checks/check-jwt.php
docker compose exec -T -u www-data crm php /opt/checks/check-callback.php
./scripts/check-resources.sh
# Создаёт 9 документов и добавляет события в аудит:
docker compose exec -T -u www-data crm php /opt/checks/check-documents.php
```

```sh
docker compose -f compose.yaml -f compose.cmwedding.yaml --profile office ps
docker compose -f compose.yaml -f compose.cmwedding.yaml --profile office logs -f
# Сохраняет данные:
docker compose -f compose.yaml -f compose.cmwedding.yaml --profile office down
```

Данные хранятся в volumes; `down -v` удаляет их. Повторный запуск не дублирует исходные демокарточки. Проверочные сценарии оставляют тестовые события в журнале.

## Пакетная генерация, аудит и выход

В разделе «Документы» кнопка «Создать документы для нескольких сотрудников» открывает пакетную генерацию: до 20 человек, один шаблон и общие параметры, отдельные DOCX/PDF для каждого и общий ZIP. Имена и кадровые сведения берутся из карточки каждого человека. Подробности — в инструкциях приложения.

Раздел «Аудит» показывает автора, время, значения «Было / Стало», изменение связей и снимки удалённых записей. Есть фильтры и история одной записи. Кнопка «Выйти» справа сверху завершает серверную сессию.

Дополнительные проверки:

```sh
docker compose exec -T crm php /opt/checks/check-audit-history.php
docker compose exec -T crm php /opt/checks/check-batch.php
python3 scripts/check-logout.py
```

## Развёртывание на отдельном сервере

Создайте `.env` по `.env.server.example`, задайте адрес сервера и уникальные пароли, затем запустите:

```sh
docker compose -f compose.yaml -f compose.cmwedding.yaml -f compose.server.yaml --profile office up -d --build --wait
```

Серверный override публикует CRM на порту 8080 и ONLYOFFICE на 8082, включает автозапуск контейнеров и поддержку сессий при смене IP клиента. Пароли серверных учётных записей после установки/миграции применяются скриптом `scripts/server-post-migration.php`. Для обновления кода с резервной копией укажите свой ключ и SSH-адрес:

```sh
./scripts/update-server.sh /path/to/ssh-key root@your-server
```

В репозитории находятся исходники, вымышленные демоданные и исходные шаблоны. Рабочие `.env`, доступы, ключи, база, сформированные документы и локальные скриншоты исключены из Git. Рабочие данные сохраняются в Docker volumes и не переносятся через Git.
