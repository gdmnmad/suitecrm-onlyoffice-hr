# Готовность кадрового демостенда

Рабочий запуск: `scripts/start.sh`, `compose.yaml` + `compose.cmwedding.yaml`. SuiteCRM 8.10.2, MariaDB 10.11.14, проверенный cmwedding ONLYOFFICE 7.2.2.56 и внешний RabbitMQ. API подтвердил действие патча и лимит 9999 соединений. [Протокол проверки](cmwedding-test.md). Возврат к исходному Community: `scripts/start.sh legacy`.

## Реализовано

- Три вымышленных сотрудника; карточки отделены от логинов CRM.
- Награды, служба, образование, родственники — связанные записи, отображаемые в карточке.
- Руководитель со ссылкой на другую карточку, запрет циклов.
- Роли кадровика и просмотра, неизменяемый штатными операциями журнал аудита.
- Аудит создания, изменения, удаления и связей; старые/новые значения, автор, дата.
- Мягкое удаление сотрудника и его дочерних записей.
- Три заранее созданных DOCX-шаблона с content controls в `data/templates`.
- Генерация DOCX/PDF средствами ONLYOFFICE через `/docbuilder`.
- Таблицы переменной длины, пустые награды, текущий период службы.
- История документов, снимок данных, хеш шаблона, автор и версия.
- Браузерный редактор и редактирование шаблонов администратором.
- JWT, подписанные временные ссылки, проверка адреса ONLYOFFICE, callback сохранения и аудит.

Приложенная справка изучена как образец структуры. Её файл и персональные данные не копируются в демоданные. Точное воспроизведение справки, фото, история контрактов, командировок и участия в событиях не входят в текущие три шаблона.

## Проверено

- Карточки и связанные разделы открыты в браузере.
- Проверки CRM: create/update/delete, автор, старые/новые значения, циклы руководителей, роли, каскадное мягкое удаление.
- JWT: корректная подпись, подмена, истечение срока. Запросы файлов без подписи и обход пути отклоняются.
- Все 9 комбинаций «3 человека × 3 шаблона» успешно генерируют DOCX и PDF на исходном Community.
- 3 шаблона и 9 результатов отрендерены bundled LibreOffice; страницы просмотрены, кириллица и таблицы читаются без обрезания.
- Редактор открыл документ без предупреждения callback после передачи Authorization через Apache.
- Подписанный callback сохранил реально изменённый ONLYOFFICE DOCX, перевёл публичный URL во внутренний, увеличил версию; проверено содержимое файла. Автоматизированный ввод в iframe встроенного браузера недоступен, поэтому изменение для этого теста выполнено Builder API.

## Проверки предложенных патчей

`aleho/onlyoffice-ce-docker-license`: готовый образ недоступен. Исправлены архивные зависимости/цели сборки, серверные бинарники собраны, мобильная сборка остановилась на svgo. Сервер не работает: в опубликованном теге нет требуемого postgreSqlBaseConnector.js. Эксперимент сохранён в отдельном Dockerfile/Compose, рабочий запуск его не использует.

`Zegorax/OnlyOffice-Unlimited`: в проверенных Developer-бинарниках 6.3.1.32 не найден ожидаемый PEM-ключ. Проверка остановила сборку; успешное применение не заявляется.

## Ограничения

ONLYOFFICE 7.2.2.56 — старый архивный выпуск для локального демонстрационного стенда. Переход на актуальную поставку с подходящим Builder — следующий этап. Исходный PDF не обновляется после ручных правок DOCX. Аудит приложения не защищает от администратора БД. Порты доступны только на localhost. Реальные персональные данные в демонстрации не используются.


## Кадровый интерфейс

Добавлены общая навигация, инструкции и вымышленные образцы, каталог документов с поиском, каталог шаблонов с созданием копии администратором, читабельный аудит. Штатные карточки сгруппированы, колонки списков настроены по смыслу. В штатных формах создания и изменения есть примеры и ссылки на помощь. Длинные технические ID сохранены как ключи; интерфейс показывает ФИО, названия, дату, автора и версию.

Форма генерации сохраняет параметры после отправки в текущей сессии по пользователю и сотруднику, показывает конкретные ошибки, использует POST/303/GET и состояние отправки. В браузере проверены ошибка пустых дат без сброса текста, успешная генерация, повторная генерация и обновление без дубля. Новая копия шаблона действительно генерирует DOCX; создание запрещено кадровику. Каталог, помощь и аудит проверены под разными ролями. Роли, CRUD-аудит, циклы руководителей и JWT проходят проверки.
