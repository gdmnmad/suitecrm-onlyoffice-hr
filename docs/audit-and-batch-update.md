# История изменений и пакетная генерация

Аудит кадровых модулей: сотрудники, награды, служба, образование, родственники. Для создания и удаления сохраняется снимок данных; для изменения — старые и новые значения. Автор берётся из текущего пользователя CRM; в callback ONLYOFFICE — из подписанных сведений о действии. Если установить автора callback невозможно, событие помечается system, а не приписывается создателю документа.

Исправлено чтение старых описаний событий, которые SuiteCRM возвращает с HTML-кодированием. Старые события с сохранённым JSON снова читаются. Изменения, которые ранее вообще не записались, задним числом восстановить невозможно.

В журнале видны автор, время, раздел, запись и таблица «Было / Стало». Есть фильтры по автору, разделу и операции, история отдельной записи. Изменение связей сериализуется без внутренних объектов CRM. Пароли и сессии в события не включаются. Журнал закрыт для редактирования штатными правами. Прямые изменения SQL вне CRM этим механизмом не отслеживаются.

Пакетная генерация доступна через «Документы → Создать документы для нескольких сотрудников». До 20 человек за запуск; один шаблон и общие параметры. Каждому создаются персональные DOCX и PDF, сохраняются собственный снимок и событие генерации. Результаты можно скачать ZIP-архивом. Архив доступен автору или администратору с проверкой доступа к каждому сотруднику. Значение «Звание и ФИО заявителя» не копируется на весь пакет: имя берётся из карточки каждого человека.

Обновление только кода, с резервной копией приложения и базы:

```sh
./scripts/update-server.sh runtime/deploy-audit-key root@your-server
```

Пароли, база и созданные документы при обновлении не заменяются. Требуется действующий SSH-ключ сервера. После успешной проверки временный ключ следует удалить из authorized_keys.

Проверки внутри CRM-контейнера:

```sh
php /opt/checks/check-audit-history.php
php /opt/checks/check-batch.php
php /opt/checks/check-crm.php
php /opt/checks/check-delete.php
php /opt/checks/check-permissions.php
```

Проверки аудита создают и мягко удаляют явно помеченные тестовые записи; журнал тестовых событий остаётся. Проверка пакета создаёт три тестовых рапорта и ZIP из шести файлов.
